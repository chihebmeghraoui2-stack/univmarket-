ESCROW SYSTEM — TRUST FEATURE #1 (CRITICAL FOR ALGERIA)
━━━━━━━━━━━━━━━━━━━━━━━━

This is the most critical trust feature. In Algeria, paying before receiving = huge psychological barrier. The escrow solves this entirely.

COMPLETE FLOW:
1. Client places order → selects payment method (PayPal / CIB / BaridiMob / Dahabia)
2. Payment confirmed (by PayPal SDK instantly, or by admin for manual payments) → escrow_transaction created with status=held
3. Seller receives notification → has 24h to accept or auto-cancel
4. Seller accepts → digital contract auto-generated → both parties sign → status=in_progress
5. Seller works → uploads deliverable files via secure delivery system → marks as delivered
6. Client downloads files → has 72h to confirm or open dispute
7a. Client confirms delivery → escrow released to seller wallet (minus platform commission) → status=released → certificate generated
7b. Client opens dispute → escrow frozen → status=disputed → admin mediates
7c. 72h pass without action → auto-release → scheduled job triggers
8. Seller requests withdrawal from wallet → admin approves → transferred to CIB/BaridiMob/PayPal

SELLER WALLET:
- balance = confirmed released funds
- pending_balance = held in escrow (not yet released)
- Withdrawal minimum: 1000 DZD
- Withdrawal methods: CIB bank transfer, BaridiMob, Dahabia, PayPal
- Withdrawal processed within 48h by admin
- Full wallet transaction history with CSV export

SECURE FILE DELIVERY SYSTEM
━━━━━━━━━━━━━━━━━━━━━━━━

- Seller uploads deliverable (PDF, DOCX, ZIP, PPT, MP4) → Cloudinary private/authenticated URL
- File linked to order_id in delivery_files table
- Unique one-time download token generated per file (UUID + HMAC signature)
- Token valid 48h or max 3 downloads, whichever comes first
- Client only sees download button after order status = delivered
- Every download logged: timestamp, IP, user-agent
- AES-256 encryption on file metadata in DB
- Admin can revoke access to any file at any time
- Automatic virus scan simulation flag for ZIP files (admin must approve before client access)

DELIVERY CERTIFICATE:
- After client confirms reception → PDF certificate auto-generated
- Certificate contains: order ID, service title, seller name + wilaya, client name, completion date, QR code
- QR code links to public verification page: /verify/[certificate-id]
- Certificate stored on Cloudinary, downloadable by both parties forever

Scheduled Laravel jobs (every 15 minutes):

- Order accepted, deadline passed + 24h grace → auto-flag → seller penalized 10% of order value → client notified to request refund
- Order delivered, client inactive > 72h → auto-release escrow to seller
- All auto-actions logged in cancellation_logs

Manual cancellation rules:
- Client can cancel free within 2h of placing order (before seller accepts)
- Client cancels after seller accepted → 20% penalty charged to client (goes to seller)
- Seller cancels after accepting → 15% penalty from seller wallet → full refund to client
- Admin can override any penalty

- 50–69: "Vendeur Actif" (bronze badge)

Sellers flagged for fraud automatically if trust score drops below 30 → admin alert.

ANTI-FRAUD SYSTEM — MAXIMUM SECURITY

  * Flag accounts created same IP as banned account
  * Flag services with identical descriptions (plagiarism detection via cosine similarity)
  * Flag abnormal order patterns (100+ orders in 1 hour = bot detection)
- All fraud flags stored in fraud_flags table → admin review queue
- 2FA mandatory for all sellers (TOTP via Google Authenticator / Authy)
- 2FA optional for clients (encouraged during onboarding)
- IP logging on all sensitive actions: login, payment, contract signing, file download, withdrawal request
- CSRF, XSS, SQL injection protection via Laravel defaults + Eloquent ORM
- Rate limiting: 60 req/min authenticated, 20 req/min unauthenticated
- AES-256 encryption for: bank account details, 2FA secrets, sensitive withdrawal data
